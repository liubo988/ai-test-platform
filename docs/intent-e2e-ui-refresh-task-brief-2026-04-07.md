# Task Brief

## 标题
- `/intent-e2e` 工作台 UI 收口与控制台化改造

## 背景
- 当前 `/intent-e2e` 已经把实时日志、执行中心、上下文、编译结果和治理学习拆开，但整体仍偏“卡片套卡片”的后台表单气质。
- 从实际使用者视角看，页面的主焦点还不够稳定：浏览器实时画面、实时日志、运行状态和任务输入同时争抢注意力。
- 当前还存在重复标题、重复说明卡、英文/中文混杂命名、空态占位过重、左右面板信息密度失衡等 UI 问题。

## 本轮目标
- 只改 `/intent-e2e` 的 UI 版式、视觉层级、命名与信息组织，不改任何业务逻辑、接口契约或运行状态逻辑。
- 把页面收口成“左侧实时日志控制台 + 右侧执行舞台”的更简洁结构，让浏览器实时画面成为真正主舞台。
- 减少不必要的壳层、说明卡和重复标题，统一页面的中文命名与视觉语气。

## 视觉方向
- Visual thesis：冷静、克制、偏专业操作台的浅色界面，不走暖米色，也不走黑色控制室路线。
- Content plan：顶部轻量页头负责定位；左侧只保留日志与少量控制；右侧先看执行，再切上下文、任务输入、治理和编译。
- Interaction thesis：
  - 主按钮区收成一排，形成明确启动动作。
  - 左栏折叠后只保留最小控制入口，不再维持笨重的次级导航。
  - tab 内尽量直接进入内容，减少“标题卡 -> 说明卡 -> 内容卡”的重复过渡。

## 验收标准
- [ ] 浏览器实时画面在右侧成为最显眼的核心区域，明显强于其余内容块。
- [ ] 左侧“实时日志”更像控制台，空态、状态、日志列表的组织更紧凑，不再出现大面积无效留白。
- [ ] 右侧 tab 内的重复说明卡显著减少，页面纵向空间利用率提升。
- [ ] 任务输入区的视觉层级更清楚，`测试目标 / 目标 URL / 参考图` 作为一个整体被感知。
- [ ] 页面文案命名更统一，优先中文化，减少中英文混杂导致的扫描阻力。
- [ ] 左栏折叠态更轻、更干净，不再成为视觉噪音。
- [ ] 不改业务功能：启动、停止、清空、tab 切换、日志滚动、弹框滚动、上下文配置、编译结果查看等行为保持可用。

## 计划修改点
- 新增全局页头，收口页面定位和返回动作。
- 重做左侧实时日志区的头部、状态条、空态和折叠态。
- 简化右侧执行中心的 header 和 tab 容器，减少重复文案与重复卡片。
- 重构任务输入区的版式，让启动控制、目标、URL、参考图形成一个更清楚的整体。
- 优化浏览器实时画面的包裹层与空态，使其更接近“主舞台”而不是普通卡片。
- 统一主要用户可见文案的中英文命名。

## 风险 / 未覆盖
- 当前组件较大，UI 收口会集中修改同一文件，需注意避免误伤已有状态逻辑。
- 这轮优先处理桌面主工作台，不单独扩展新的移动端专属交互。
- 不会在本轮引入新的图标系统、设计 token 文件或组件拆分。
